# do-claude-optimizations (dco) — consolidated spec

**Status:** adopted (Phases 0–6 shipped; later phases in-flight/planned)
**Date:** 2026-05-26
**Scope:** qagents-wide (the memory topic-file tree + every `CLAUDE.md` in
the repo)
**Tests:** a companion bash suite (`-tests/`)

_Redacted public rendering. Operator absolute paths are genericized to
`<repo>` / `<wt>` / `<memory>`; activation dates are referred to as "the
credit-activation date". The engineering content — the fan-out shape, the
zero-prompt requirement, the diff-block authoring rules, the exit-code
contract — is preserved, because that is the methodology this repo
publishes._

This consolidated spec supersedes two predecessor specs and pins
**zero-prompt fan-out** as a load-bearing acceptance criterion.

## 1. Motivation

Three monotonic pressures + one operational reality:

1. **Memory-index truncation.** The harness warns at session start when the
   index exceeds its line cap; entries below the cap are unreachable that
   session.
2. **CLAUDE.md size pressure** across subprojects. The close skill's warn +
   fail caps are emergency brakes; without active trimming they're only ever
   pulled.
3. **Stale information persists in two layers** — git history + the recall
   index already preserve "what was true at T". Memory + CLAUDE.md are
   supposed to be "what's true now"; each drifts toward an audit log.
4. **Two billing surfaces.** Before the programmatic-credit activation date,
   every SDK call bills at the API rate card, while interactive sessions are
   already covered by the subscription. So dco needs **two coexistent
   invocation lanes** — an SDK/cron lane (autonomous; gated until the credit
   activates) and a manual/interactive lane (orchestrated by main-session
   Claude via the Agent tool; available unconditionally). Both lanes share
   every mechanical subcommand and every subagent prompt; only the
   orchestrator differs.

The close skill's size-cap exit is the emergency brake; dco is the
continuous trim that keeps the brake from being triggered.

## 2. Design — coordinator + fan-out

dco runs as a coordinator that fans out into one Opus subagent per CLAUDE.md
target plus a memory-index digester plus a sequential cross-cutting
digester, returning digests the coordinator merges into a single apply-plan.

**Why subagents:** (1) context budget — reading every CLAUDE.md + every
memory file in one context costs tens of K of tokens; fan-out scopes each
subagent to one CLAUDE.md + its referenced memory; (2) independent judgment
— "is this paragraph still load-bearing?" is domain-specific, so a
clean-context subagent trims better than a generalist pass; (3) bounded
blast radius — a bug in one digest hits one subproject.

**Fan-out shape:** one `dco-subproject` digester per subproject (plus one
parameterized for the root CLAUDE.md), one `dco-memory` digester for the
index + topic files (these run in parallel), then one sequential `dco-cross`
that reads every per-sub digest + the cross-cutting memory file list and is
authoritative on multi-subproject memory files. Each digester writes to a
gitignored buffer (`pending/dco-digests/`).

**Lane comparison.** The SDK/cron lane enters via a launchd timer → an
asyncio SDK orchestrator; the manual lane enters via the operator typing the
manual skill and is orchestrated by main-session Claude issuing the Agent
tool calls. The subagent prompt files are **the same** across lanes (the
Agent tool resolves them by `subagent_type` registration; the SDK consumes
them as system prompts). The manual lane reuses every artifact except the
two SDK-bound drivers.

**Digest schema.** Each digest carries: `## Size before`, `## Proposed trims
(concrete diffs)` (one or more `### Trim N` blocks, each with `File:` /
`Lines:` / `Reason:` / an Edit-tool-ready `old_string: |` + `new_string: |`),
optional `## Proposed memory updates`, `## Skipped (reviewed; left as-is)`,
`## Expected size after`, and `## Self-check` (anchors preserved,
cross-references unchanged). If a digester can't find enough trims to hit the
soft target, it emits `BLOCKED — <reason>` and stops; the coordinator
surfaces BLOCKED items in the footer.

**Cross-cutting conflict resolution.** (1) per-sub proposes a trim but the
cross-cutting file is still load-bearing → drop per-sub, list in Skipped;
(2) multiple per-sub digests propose the same trim → keep, attribute to all;
(3) per-sub digests disagree → keep neither, surface as BLOCKED for operator
triage; (4) per-sub trim against a non-cross-cutting file → ignore.

**Apply phase.** The coordinator does not re-judge — it applies digests
as-is: write the concatenated plan to a buffer (audit + rollback marker),
acquire both sentinels, parse + validate every trim against the allow-list
(CLAUDE.md anywhere OR a memory file), run the **sequential-simulation
dry-run** (below) before any mutation, back up each target, apply in plan
order, commit the memory tree + the canonical tree separately, release both
sentinels, emit the footer. On any failure: halt at the first failure (do
not roll back already-applied edits — they're correct per the digest), write
a FAILED marker, release both sentinels, exit 50.

**Why no worktree.** dco runs unattended in ~5–15 min and produces a single
commit; a worktree would add provisioning cost for no benefit. The trade-off
— writing to `main` directly — is covered by the lock-compatibility refusal
(§ 5).

## 3. Manual-lane orchestration sequence

The manual skill instructs main-session Claude to: (1) pre-flight; (2)
acquire both sentinels; (3) **permit-fanout** — verify the zero-prompt
allow-list is in place (refuse with exit 61 if a required pattern is
missing); (4) **Phase A** — one message with the parallel digest fan-out
(one call per subproject + root + the memory digester; split into two waves
if the harness refuses the full parallel block); (5) **Phase B** — a
separate message with the single sequential cross-cutting call
(message-level sequencing ensures B starts after A); (6) plan concat; (7)
operator review of the plan's summary table; (8) apply (if continue); (9)
release sentinels; (10) footer. Steps 1–3, 6, 8–10 are pure shell (no
tokens); steps 4–5 are the only LLM-billed work, billed against the
interactive quota under the manual lane.

**Why main-session orchestration, not a delegated coordinator:** (1)
operator-in-loop visibility — the operator sees each phase land and can
intervene between A and B; (2) token cost — a delegated coordinator means
main-session Claude **plus** coordinator Claude **plus** the sub-Claudes;
main-session-as-orchestrator skips the middle layer; (3) failure recovery —
main-session can re-run just one malformed digest, where coordinator
delegation re-runs the whole coordinator. The subagent behavior is invariant
across lanes: "read inputs, write digest, return one line."

## 4. Zero-prompt fan-out (load-bearing)

**Requirement.** During the fan-out the operator is prompted **exactly 0
times**. An early run drew 50+ prompts from compound shell idioms emitted by
the per-sub digesters — that is the bug class this section eliminates.

**Root cause.** Compound shell commands (chains with `;` / `&&` / `||`,
pipes, redirections, command substitution, here-docs) are inspected by the
permission layer as a **single whole-line pattern**, not per-leaf. Even when
each leaf binary has an allow-rule, the compound form draws a prompt (a
trailing `; echo "exit=$?"` was enough). A second class: a subdirectory
mismatch — a `scripts/*.sh` glob matches direct children only, so a helper
one directory deeper draws a prompt.

**Three layers of mitigation.** (A) **Agent-prompt discipline** — every
digester prompt pins "Bash calls MUST be a single command; no `;` / `&&` /
`||` / pipes / redirections / top-level command substitution / here-docs; if
you need an exit code, call the helper that captures it." The agent's only
callable surface is the dco helper scripts plus pure Read. (B) **Allow-list**
— the settings file carries the helper-directory pattern in each call-shape
variant the agent may use, committed (not local-only) so a fresh worktree
inherits them. **The pattern uses a bare trailing `*` on a fully-literal
prefix**, not a mid-string `*.sh:*`: the colon-suffix matcher recognizes only
the trailing wildcard and treats everything before the colon — including a
mid-string glob — as a **literal**, so `dco-helpers/*.sh:*` matched only a
command literally containing `*.sh`, i.e. never; the bare-trailing-`*` form
(`Bash(.../dco-helpers/*)`) matches the prefix followed by any sequence
including spaces, so one rule covers every helper + every argument. (C)
**Pre-fanout validator** — a `--permit-fanout` subcommand asserts each
required pattern is present (exit 0 / exit 61), called before Phase A; refuse
to spawn agents if it fails. (The substring check is necessary but not
sufficient — it confirms the string is present, not that the matcher honors
it; the trailing-`*` form is what makes it honored.)

**Helper inventory** (the zero-prompt callable surface): each is a single
script taking simple args, no chained-command argument — a recent-summary
grep, a git-touched lookup, a cross-cutting-memory lister, a memory-ref
finder, a summary-text reader. The Read tool covers all file reads. A new
helper in the same directory needs no settings change; a new helper
*directory* gets a new pattern in the same change.

## 5. Lock posture + safety

**Acquisition order:** (1) lock-compatibility — refuse if **any** session
lock branch exists (no retry, no waiting; exit 10 with the conflicting
branch list — the cron lane tries again next night); (2) acquire the data
write-lock (exit 19 if held); (3) acquire the dot-claude sentinel (if held,
release (2) first; exit 19). No partial-lock state; release order is the
reverse. The read phase needs no locks (each subagent has its own context);
the apply phase re-reads to verify no drift since digest emission. **Backup
before each apply** — the target's current content is copied to a gitignored,
7-day-retained backup dir; the `.bak` is the rollback source.

**What dco does NOT touch:** any file outside CLAUDE.md + the memory tree;
spec files; subproject plan/memory files; the legal tree; source code,
tests, or configuration; the historical summaries; git history. A digest
proposing an edit outside the allowed surface is dropped + logged
(belt-and-suspenders over the agent-prompt forbiddance).

## 6. Diff-block authoring (load-bearing)

The apply tool parses `old_string: |` + `new_string: |` as literal block
scalars. Four authoring rules, enforced at parse so no LLM round-trip is
needed to surface the bug:

1. **Bare `|` only.** An explicit `|N` indentation indicator is rejected at
   parse (exit 51). It produced an apply failure where the parser stripped
   the wrong number of columns and the `old_string` wasn't found.
2. **First content line at `parent_indent + 2`.** Deeper is rejected
   (`non-standard body indent`, exit 51) — the literal-block auto-detects its
   body indent from the first content line, so content written at the wrong
   column strip-mismatches the target file.
3. **No mixed mid-block indent.** A line between the parent indent and the
   body indent is rejected (`mixed indentation`, exit 51) — formerly
   silently truncated.
4. **Rescue when (2) is unsatisfiable** — *anchor-expansion* (preferred):
   extend the `old_string` upward to include a column-0 line in the file,
   then write content at the standard body indent so the strip preserves the
   file's actual indents. Fallback: move the trim to `## Skipped` with the
   deep-indent reason.

**Unique-context rule.** A trim whose `old_string` body could appear more
than once in the post-prior-edits target MUST include ≥ 1 line of unique
surrounding context. **Sequential-simulation validation:** the dry-run runs
trims in plan order against an in-memory copy, catching "trim N becomes
ambiguous because trim N-1 inserted the same body" — on ambiguity, exit 51,
no mutation, before `--execute` is ever called.

## 7. Triggers + reference data

The fan-out list is the known-projects set minus the whole-repo name (root
gets its own pass), plus the memory + cross digesters. **Size targets:** the
memory index to a hard cap with headroom under the truncation limit; every
CLAUDE.md to a soft target with headroom under the warn cap; a floor below
which no trim drops a file. **What counts as stale:** the described
code/state no longer exists; a more recent close summary fully covers it; it
duplicates a sibling CLAUDE.md (cross-reference instead); it was a dated
status snapshot a later session superseded — **except** the protected
append-only dated status blocks in the litigation subprojects. The cron lane
is a nightly timer (opt-in `--enable`; the date guard refuses SDK fires
before the credit-activation date); the manual lane is available
unconditionally and is the only lane before that date.

## 8. Exit codes

0 ok · 10 lock-compat (session branch present) · 12 canonical not-clean ·
13 pre-existing FAILED marker · 19 sentinel held · 20 unknown · 50 apply
failed mid-execute · 51 malformed digest / forbidden `|N` / deep-or-mixed
indent / sequential-simulation ambiguity (pre-mutation) · 52 plan already has
an `.applied` sidecar · 60 SDK lane disabled pre-activation (use the manual
lane) · 61 a required allow-list pattern is missing.

## 9. Phases

- **[shipped]** Phase 0 — spec adoption + script skeleton + helper scripts +
  the orchestrator skill (structure only, no subagent calls yet).
- **[shipped]** Phase 1 — SDK lane: the digest subcommand + SDK driver, the
  mechanical plan concat, the apply + backup + FAILED-marker + commit, the
  asyncio coordinator with bounded concurrency + a simulate mode.
- **[shipped]** Phase 2 — operator-eyeball gate: the nightly plan is written
  but not applied until review; explicit `--plan-path` + an `.applied`
  sidecar + double-apply refusal (exit 52) + a list-plans subcommand + a
  plan summary header.
- **[planned]** Phase 3 — auto-apply after an observation window of unanimous
  approvals; plans still written for audit.
- **[shipped]** Phase 4 — cron registration; the timer is the operator's
  explicit `--enable`.
- **[planned]** Phase 5 — migrate to the EC2 cron lane in lockstep with the
  cron migration.
- **[shipped]** Phase 6 — the manual-interactive lane + the date guard
  (exit 60) + an override env var.
- **[shipped]** Phase 7 + 7.1 — zero-prompt fan-out + the first-run apply-plan

  unique-context pins; new helpers; the `--permit-fanout` validator + the
  trailing-`*` allow-list; the deep-indent + mixed-indent + anchor-expansion

## 10. Acceptance criteria

~28 criteria, each mapped to a bash test: spec hygiene; skill + scripts +
agents in place (each agent `model: opus`); exit-code coverage; lock posture
documented; subagent-prompt safety (no edits outside the allow-list);
uniform footer; cron registration; the digest/plan/apply subcommands; the
SDK simulate path (the real SDK invocation deferred until the credit
activates); the Phase-2 sidecar gate + list-plans; the date guard (shell +
coordinator); the `|N` rejection; sequential-simulation; the widened summary
count; the zero-prompt allow-list + `--permit-fanout`; the agent
no-compound-command pins; deep-indent + mixed-indent parse-rejection; the
anchor-expansion guidance in prompts; and two manual-acceptance items — zero
prompts in a real run, and the size targets met post-auto-apply.
